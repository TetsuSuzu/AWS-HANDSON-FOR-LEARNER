# 手順 1：DynamoDB テーブルを作る

会員のデータを保存する表（テーブル）を作ります。

## 1-1. DynamoDB の画面を開く

1. AWS マネジメントコンソールの検索欄に **DynamoDB** と入力し、サービスを開く
2. 画面右上のリージョンが **アジア パシフィック（東京）ap-northeast-1** になっていることを確認する

## 1-2. テーブルを作成する

1. 左のメニューの **テーブル** → 右上の **テーブルの作成** をクリック
2. 次のとおり入力する

| 項目 | 入力する値 | 意味 |
|---|---|---|
| テーブル名 | `users-table-<名前>` | 表の名前 |
| パーティションキー | `id` | 1 件ごとのデータを見分ける目印 |
| パーティションキーのデータ型 | **文字列** | `id` は `u-0001` のような文字で表すため |

> **パーティションキーとは？**
> 表の 1 行（会員 1 人）を一意に見分ける値です。同じ `id` の行は 2 つ作れません。この教材では、登録のときに `id` を指定します。

3. 下のほうの **テーブル設定** は **カスタマイズ設定** を選ぶ
4. **キャパシティーモード** で **オンデマンド** を選ぶ
   - オンデマンドは、使った分だけ料金がかかる方式です。練習に向いています。
5. その他の設定は既定のまま
6. 一番下の **テーブルの作成** をクリック

## 1-3. 確認する

- テーブルの一覧に `users-table-<名前>` が表示され、**ステータス** が **アクティブ** になるまで待つ（数秒〜1 分）。

### 確認ポイント

- [ ] テーブル名が `users-table-<名前>`
- [ ] パーティションキーが `id`（文字列）
- [ ] ステータスが **アクティブ**

## 1-4. テーブルに 1 件入れてみる（任意）

Lambda より前に、画面からデータを入れて、テーブルの仕組みを確かめます。

1. `users-table-<名前>` テーブルを開く → **項目を探索** → **項目の作成**
2. 次のように入力する（`id` 以外の項目は、後の手順で Lambda が扱うため、ここでは `id` だけで構いません）

| 属性名 | 型 | 値 |
|---|---|---|
| `id` | 文字列 | `test-0001` |

3. **項目の作成** をクリック
4. 一覧に `test-0001` が表示されれば成功。確認後、この項目は削除してかまいません（後の手順の動作確認を見やすくするため）。

> **ポイント**: DynamoDB は「列の数を事前に決めない」表です。`name` や `email` などは、データを入れるときに自由に追加できます。このため、Lambda 側で項目の形を決めて保存します。

## 1-5. PartiQL エディタでデータを確かめる（任意）

PartiQL は、SQL に似た命令でテーブルのデータを読んだり書いたりする仕組みです。DynamoDB の画面にある **PartiQL エディタ** で、プログラムを書かずに中身を確かめられます。

1. `users-table-<名前>` テーブルを開く
2. 画面上部の **PartiQL エディタ** を開く
3. 次の命令を入力し、**実行** をクリックする

   ```sql
   SELECT * FROM "users-table-<名前>"
   ```

   - 結果に、テーブルの全件が表示されます。Lambda のテストで登録した会員が表示されれば、登録は成功しています。
   - テーブル名は、ダブルクォート（`"`）で囲みます。

4. 特定の会員だけを探すときは、`WHERE` を付けます。

   ```sql
   SELECT * FROM "users-table-<名前>" WHERE id = 'u-0001'
   ```

> **注意**
> - `UPDATE` と `DELETE` は、すぐにデータに反映され、取り消しはできません。
> - `WHERE` を付けずに `DELETE` を実行すると、テーブルのデータがすべて削除されます。この教材では、まず `SELECT` で確かめてから、必要な操作をしてください。

### 確認ポイント

- [ ] `SELECT * FROM "users-table-<名前>"` で、登録した会員が表示される
