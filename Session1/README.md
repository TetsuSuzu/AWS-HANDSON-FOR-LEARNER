# AWS ハンズオン：静的ウェブサイトを S3 で公開しよう

> このセッションのコードは [gist](https://gist.github.com/TetsuSuzu/85e34b4acd299711ee18f6161205fe3f) にあります。`Session1_` で始まるファイルを開き、中身をコピーして使えます。

## このハンズオンで作るもの

写真と会員登録フォームを含む **静的ウェブサイト** を Amazon S3 でホスティングして公開します。会員登録フォームは Session3 で API に接続します。

> **S3 バケットは 2 つに分けます**: 会員向けサイト（`index.html`）は、この Session で作るバケットに置きます。管理者用の画面（`admin.html`）は、個人情報を扱うため **別のバケット** に置きます。管理画面用のバケットは Session4 で作ります。

```
【全体構成】

ブラウザ
  │
  │ URLでアクセス
  ▼
┌─────────────┐
│  Amazon S3  │  ← 静的ウェブサイトホスティング（HTML/CSS/画像を公開）
└─────────────┘
```

## 使用するファイル

| ファイル名 | 用途 |
|---|---|
| `index.html` | ウェブサイトのメインページ（HTML。S3 にアップロードする） |
| `app.js` | 会員登録と料理のおすすめの動き（JavaScript。S3 にアップロードする） |
| `admin.html` | 管理者用の会員管理画面（Session4 で使う。**別の S3 バケット** に置くため、この Session ではアップロードしない） |
| `admin.js` | 会員管理画面の動き（JavaScript。`admin.html` と同じく Session4 で使う） |
| `styles.css` | ウェブサイトのデザイン設定 |
| `photo1.png` | おすすめ風景①の画像（かぐらスキー場） |
| `photo2.png` | おすすめ風景②の画像（富津海岸から望む富士山） |
| `config.js` | 会員 API・管理 API・Bedrock API のエンドポイント（Session3・4・6 で設定する）。会員向けサイトと管理画面の両方に置く |
| `Bucketpolicy.txt` | S3 バケットを公開するためのポリシー設定 |

---

## 手順の流れ

1. S3 バケットを作成する
2. ファイルをアップロードする
3. 静的ウェブサイトホスティングを有効にする
4. バケットポリシーを設定する（公開許可）
5. 動作確認

---

## Step 1：S3 バケットを作成する

### 1-1. S3 の画面を開く

1. AWS マネジメントコンソールにログイン
2. 画面上部の検索バーに `S3` と入力して選択
3. **「バケットを作成」** ボタンをクリック

### 1-2. バケットを設定する

| 項目 | 値 |
|---|---|
| バケット名 | <font color="red">lastname-firstname</font>（例：`yamada-taro`）。会員向けサイト用 |
| AWS リージョン | **アジアパシフィック（東京） ap-northeast-1** |
| パブリックアクセスをすべてブロック | **チェックを外す（ブロックを無効にする）** |

> 「現在の設定により～」という警告が出ますが、今回は公開サイトを作るため無効にします。確認チェックボックスにチェックを入れて進みます。

「バケットを作成」をクリック

---

## Step 2：ファイルをアップロードする

1. 作成したバケットをクリックして開く
2. **「アップロード」** ボタンをクリック
3. **「ファイルを追加」** をクリックし、以下の 6 ファイルをすべて選択：
   - `index.html`
   - `app.js`
   - `styles.css`
   - `photo1.png`
   - `photo2.png`
   - `config.js`
4. **「アップロード」** をクリック

> 6 ファイルすべてが「成功しました」と表示されれば OK です。`admin.html` と `admin.js` は、ここではアップロードしません（Session4 で別のバケットに置きます）。Session1 の時点では `config.js` の API URL は空なので、会員登録は Session3、料理のおすすめは Session6 の設定後に使えます。

---

## Step 3：静的ウェブサイトホスティングを有効にする

### 3-1. プロパティタブを開く

1. バケット詳細画面の **「プロパティ」** タブをクリック
2. 一番下までスクロールして **「静的ウェブサイトホスティング」** を見つける
3. **「編集」** をクリック

### 3-2. ホスティングを設定する

| 項目 | 値 |
|---|---|
| 静的ウェブサイトホスティング | **有効にする** |
| ホスティングタイプ | **静的ウェブサイトをホストする** |
| インデックスドキュメント | `index.html` |
| エラードキュメント | `index.html` |

「変更の保存」をクリック

> 設定後に **「バケットウェブサイトエンドポイント」** の URL が表示されます。これがウェブサイトの URL です。メモしておきましょう。

```
例: http://lastname-firstname.s3-website-ap-northeast-1.amazonaws.com/
```

---

## Step 4：バケットポリシーを設定する（公開許可）

バケット内のファイルを誰でも読めるようにするため、ポリシーを設定します。

### 4-1. アクセス許可タブを開く

1. バケット詳細画面の **「アクセス許可」** タブをクリック
2. **「バケットポリシー」** セクションの **「編集」** をクリック

### 4-2. ポリシーを貼り付ける

以下の JSON を貼り付けます（<font color="red">lastname-firstname</font> の部分を **自分のバケット名** に変更）：

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::lastname-firstname/*"
        }
    ]
}
```

「変更の保存」をクリック

> `Bucketpolicy.txt` の内容がこのポリシーの元になっています。バケット名の部分だけ書き換えてください。

> **公開範囲に注意**: この手順では S3 の静的ウェブサイトを公開し、誰でも HTML・CSS・画像を閲覧できるようにします。個人情報、認証情報、秘密鍵などをアップロードしないでください。

## コードの読み方（初心者向け）

このセクションでは、Session1 のファイルに書かれているコードの意味を説明します。最初からすべてを理解する必要はありません。「どこで、何をしているか」がわかれば十分です。

### 用語の説明

| 用語 | 意味 |
|---|---|
| HTML | ウェブページの骨組みを書く言葉。HyperText Markup Language の略です。`<h2>ようこそ</h2>` のように、`<` と `>` で囲んだ「タグ」で書きます |
| CSS | 見た目（色、大きさ、余白など）を決める言葉。Cascading Style Sheets の略です |
| JavaScript（JS） | ページを動かす言葉。ボタンを押したときの処理などを書きます。Java とは別の言語です |
| `var` | 「変数（データを入れておく箱）」を作る言葉です。variable（変数）の略です。`var name = "山田";` は、`name` という箱に `"山田"` を入れる、という意味です |
| `const` | 後から中身を変えない変数を作る言葉です。constant（定数）の略です |
| 関数（function） | 処理のまとまりに名前を付けたものです。`function 名前() { ... }` の形で書き、`名前()` と書くと実行されます |
| `async` / `await` | 通信のように、終わるまで時間がかかる処理を扱う言葉です。`await` は「終わるまで待つ」という意味です |
| DOM | ブラウザーが HTML を読み取ってできた、ページの部品の一覧です。JavaScript は DOM を通してページを操作します。Document Object Model の略です |
| `document` | 今開いているページ全体を表すものです |
| `document.getElementById("id名")` | 指定した `id` を持つ部品（ボタンや入力欄など）を探します |
| `addEventListener("click", ...)` | 「クリックされたら、この処理を実行する」と登録します |
| `window` | ブラウザーの窓そのものです。`window.API_ENDPOINT` は、`config.js` で設定した値を取り出すときに使います |
| `fetch` | ほかのサーバー（API）に要求を送る命令です |
| JSON | データを文字で表す形式です。`{"name": "山田"}` のように書きます。JavaScript Object Notation の略です |

### index.html（ページの骨組み・HTML）

- `<head>` の中: 文字コード（`UTF-8`）、ページのタイトル、`styles.css` の読み込みを書いています。
- `<header>` と `<nav>`: 画面上部のメニューです。`href="#photo1"` は、同じページ内の `id="photo1"` の場所へ移動するリンクです。
- `<main>` の中の `<section>`: ページの各まとまり（ようこそ、風景、会員登録、料理のおすすめ）です。
- `<form>` と `<input>`: 会員登録の入力欄です。`<label>` は入力欄の説明文です。
- `<button id="registerButton">`: 「登録」ボタンです。`id` は、`app.js` からボタンを見つけるための名前です。
- ページの最後の 2 行で、JavaScript を読み込んでいます。

```html
<script src="config.js"></script>
<script src="app.js"></script>
```

`config.js` を先に読み込むのは、`app.js` が `config.js` の値を使うためです。順番を入れ替えないでください。

### config.js（設定値）

```javascript
window.API_ENDPOINT = "";
window.SEARCH_API_ENDPOINT = "";
```

- `window.` を付けると、ほかのファイル（`app.js`）からも値を読めるようになります。
- `""` は「まだ設定していない」という意味です。空のままだと、画面に「API URL は Session3 で設定します」と表示されます。
- 設定する値は URL です。書き換え方は、[Session3 の 3-6](../Session3/README.md) で、URL の書き方を確認してください。

### app.js（ページの動き・JavaScript）

ボタンを押したときに、何をするかを書いています。

1. `document.getElementById("registerButton").addEventListener("click", ...)`
   - 「登録」ボタンがクリックされたら、`function` の中の処理を実行します。
   - `async function` は、途中で `await`（通信の終わりを待つ）を使うための書き方です。
2. `var form = document.getElementById("registrationForm");`
   - 会員登録のフォームを、`form` という変数（箱）に入れています。
3. `if (!form.reportValidity()) { return; }`
   - 入力漏れがあれば、ここで処理を終えます。`return` は「ここで終わる」という意味です。
4. `var apiEndpoint = (window.API_ENDPOINT || "").replace(/\/+$/, "");`
   - `config.js` の値を取り出します。`||` は「左が空なら右の値を使う」という意味です。
   - `.replace(/\/+$/, "")` は、URL の末尾にある `/` を取り除きます。
5. `if (!apiEndpoint) { ... }`
   - URL が未設定なら、メッセージを表示して終わります。
6. `var user = Object.fromEntries(formData.entries());` と `user.age = Number(user.age);`
   - 入力された内容を 1 つのデータ（オブジェクト）にまとめます。年齢は文字から数字に変換します。
7. `await fetch(apiEndpoint, { method: "POST", ... })`（API の URL にそのまま POST する）
   - API に、データを送ります（`POST` は「登録の要求」の意味です）。
   - `body: JSON.stringify(user)` は、JavaScript のデータを JSON の文字に変換して送るという意味です。
   - `await` で、API からの返事を待ちます。
8. `var result = await response.json();`
   - 返事の JSON を、JavaScript のデータに戻します。
9. `try { ... } catch (error) { ... }`
   - `try` は「試す」、`catch` は「エラーを受け止める」という意味です。エラーが起きても画面が壊れず、「登録に失敗しました」などのメッセージを表示します。

料理のおすすめのボタン（`recommendationButton`）も、同じ流れで書いています。違うのは、送る先（料理のおすすめの API の URL）と、受け取る項目（`result.answer`）だけです。

### styles.css（見た目・CSS）

```css
header {
    background-color: #2e7d32;
    color: white;
}
```

- `header` は「どの部品の見た目を変えるか」を表します。これを**セレクタ**と呼びます。
- `{ ... }` の中には、「見た目の項目: 値;」を書きます。
- `background-color` は背景色、`color` は文字の色です。`#2e7d32` は色を表す番号です。
- `margin` は部品の外側の余白、`padding` は部品の内側の余白です。
- `.green-button` の `.` は、`class="green-button"` が付いた部品をまとめて指定する意味です。
- `:hover` は、マウスを乗せたときの見た目を指定します。

## よくあるトラブルと対処法

### ページが表示されない（403 Forbidden エラー）

- バケットポリシーが正しく設定されているか確認
- 「パブリックアクセスをすべてブロック」がオフになっているか確認
- バケットポリシーの `Resource` のバケット名が正しいか確認

### 写真が表示されない

- `photo1.png`・`photo2.png` が S3 にアップロードされているか確認
- ファイル名が正確に一致しているか確認（大文字・小文字の違いに注意）

### AI おすすめ機能が動かない

- `index.html` は書き換えず、Session6 で `Session1/config.js` の `window.SEARCH_API_ENDPOINT` に料理のおすすめの API の URL を設定します。このセッションの時点では、おすすめ欄は「Session6 で設定します」と表示されるのが正常です
