# AWS ハンズオン：静的ウェブサイトを S3 で公開しよう

## このハンズオンで作るもの

写真と会員登録フォームを含む **静的ウェブサイト** を Amazon S3 でホスティングして公開します。会員登録フォームは Session3 で API に接続します。

```
【全体構成】

ブラウザ
  │
  │ URLでアクセス
  ▼
┌─────────────┐
│  Amazon S3  │  ← 静的ウェブサイトホスティング（HTML/CSS/画像を公開）
└─────────────┘
```

## 使用するファイル

| ファイル名 | 用途 |
|---|---|
| `index.html` | ウェブサイトのメインページ（HTML。S3 にアップロードする） |
| `app.js` | 会員登録と料理のおすすめの動き（JavaScript。S3 にアップロードする） |
| `styles.css` | ウェブサイトのデザイン設定 |
| `photo1.png` | おすすめ風景①の画像（かぐらスキー場） |
| `photo2.png` | おすすめ風景②の画像（富津海岸から望む富士山） |
| `config.js` | 会員 API と Bedrock API のエンドポイント（Session3/4 で設定する） |
| `Bucketpolicy.txt` | S3 バケットを公開するためのポリシー設定 |

---

## 手順の流れ

1. S3 バケットを作成する
2. ファイルをアップロードする
3. 静的ウェブサイトホスティングを有効にする
4. バケットポリシーを設定する（公開許可）
5. 動作確認

---

## Step 1：S3 バケットを作成する

### 1-1. S3 の画面を開く

1. AWS マネジメントコンソールにログイン
2. 画面上部の検索バーに `S3` と入力して選択
3. **「バケットを作成」** ボタンをクリック

### 1-2. バケットを設定する

| 項目 | 値 |
|---|---|
| バケット名 | <font color="red">lastname-firstname</font>（例：`yamada-taro`） |
| AWS リージョン | **アジアパシフィック（東京） ap-northeast-1** |
| オブジェクト所有者 | ACL 無効（推奨） |
| パブリックアクセスをすべてブロック | **チェックを外す（ブロックを無効にする）** |

> 「現在の設定により～」という警告が出ますが、今回は公開サイトを作るため無効にします。確認チェックボックスにチェックを入れて進みます。

「バケットを作成」をクリック

---

## Step 2：ファイルをアップロードする

1. 作成したバケットをクリックして開く
2. **「アップロード」** ボタンをクリック
3. **「ファイルを追加」** をクリックし、以下の 6 ファイルをすべて選択：
   - `index.html`
   - `app.js`
   - `styles.css`
   - `photo1.png`
   - `photo2.png`
   - `config.js`
4. **「アップロード」** をクリック

> 6 ファイルすべてが「成功しました」と表示されれば OK です。Session1 の時点では `config.js` の API URL は空なので、会員登録は Session3、料理のおすすめは Session4 の設定後に使えます。

---

## Step 3：静的ウェブサイトホスティングを有効にする

### 3-1. プロパティタブを開く

1. バケット詳細画面の **「プロパティ」** タブをクリック
2. 一番下までスクロールして **「静的ウェブサイトホスティング」** を見つける
3. **「編集」** をクリック

### 3-2. ホスティングを設定する

| 項目 | 値 |
|---|---|
| 静的ウェブサイトホスティング | **有効にする** |
| ホスティングタイプ | **静的ウェブサイトをホストする** |
| インデックスドキュメント | `index.html` |
| エラードキュメント | `index.html` |

「変更の保存」をクリック

> 設定後に **「バケットウェブサイトエンドポイント」** の URL が表示されます。これがウェブサイトの URL です。メモしておきましょう。

```
例: http://lastname-firstname.s3-website-ap-northeast-1.amazonaws.com/
```

---

## Step 4：バケットポリシーを設定する（公開許可）

バケット内のファイルを誰でも読めるようにするため、ポリシーを設定します。

### 4-1. アクセス許可タブを開く

1. バケット詳細画面の **「アクセス許可」** タブをクリック
2. **「バケットポリシー」** セクションの **「編集」** をクリック

### 4-2. ポリシーを貼り付ける

以下の JSON を貼り付けます（<font color="red">lastname-firstname</font> の部分を **自分のバケット名** に変更）：

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::lastname-firstname/*"
        }
    ]
}
```

「変更の保存」をクリック

> `Bucketpolicy.txt` の内容がこのポリシーの元になっています。バケット名の部分だけ書き換えてください。

> **公開範囲に注意**: この手順では S3 の静的ウェブサイトを公開し、誰でも HTML・CSS・画像を閲覧できるようにします。個人情報、認証情報、秘密鍵などをアップロードしないでください。

---

## Step 5：CloudFront ディストリビューションを作成する

CloudFront を S3 の前段に置くことで、**HTTPS 配信・世界規模のキャッシュ・高速配信** が実現できます。

### 5-1. CloudFront の画面を開く

1. AWS マネジメントコンソールで検索バーに `CloudFront` と入力して選択
2. **「ディストリビューションを作成」** をクリック

### 5-2. オリジンを設定する

| 項目 | 値 |
|---|---|
| オリジンドメイン | **S3 バケット一覧には出てこないので手動入力**：<font color="red">lastname-firstname.s3-website-ap-northeast-1.amazonaws.com</font> |
| プロトコル | **HTTP のみ** |

> ⚠️ ドロップダウンで表示される S3 バケット名（`xxx.s3.amazonaws.com`）は **選ばないこと**。  
> 静的ウェブサイトエンドポイント（`s3-website-ap-northeast-1`）を手動で入力してください。

### 5-3. デフォルトのキャッシュビヘイビアを設定する

| 項目 | 値 |
|---|---|
| ビューワープロトコルポリシー | **HTTP を HTTPS にリダイレクト** |
| キャッシュポリシー | **CachingOptimized**（デフォルト） |
| オリジンリクエストポリシー | なし（デフォルト） |

### 5-4. 設定を完了する

| 項目 | 値 |
|---|---|
| 料金クラス | **北米・欧州・アジア・中東・アフリカを使用**（または最安の「北米・欧州のみ」） |
| デフォルトルートオブジェクト | `index.html` |

**「ディストリビューションを作成」** をクリック

> ⏳ ディストリビューションのデプロイには **5〜10 分** かかります。  
> ステータスが「デプロイ中」→「有効」になれば完了です。

### 5-5. CloudFront ドメインを確認する

ディストリビューション一覧に表示される **「ドメイン名」** をメモします。

```
例: xxxxxxxxxxxx.cloudfront.net
```

## 次へ

S3 バケット名と公開 URL を控え、[Session2](../Session2/README.md) に進んでください。会員登録フォームの API 接続は Session3、料理のおすすめ機能は Session4 で設定します。

> ハンズオン終了後は CloudFront ディストリビューションを無効化して削除し、S3 バケットを空にして削除してください。公開状態のバケットを不要なまま残さないようにします。

このドメインを使って `https://xxxxxxxxxxxx.cloudfront.net/` でアクセスできます。

## Step 6：動作確認

### 6-1. ウェブサイトにアクセスする

CloudFront ドメインでアクセスします（HTTPS）：

```
https://xxxxxxxxxxxx.cloudfront.net/
```

S3 ウェブサイトエンドポイント（HTTP）でも引き続きアクセス可能です：

```
http://lastname-firstname.s3-website-ap-northeast-1.amazonaws.com/
```

### 6-2. 各機能を確認する

| 確認項目 | 期待する動作 |
|---|---|
| トップページが表示される | ヘッダー・ナビ・フッターが正しく表示される |
| 写真が表示される | かぐらスキー場・富津海岸の写真が表示される |
| 「新規会員募集」リンクが動く | クリックすると会員登録ページに移動する |
| AI おすすめ機能が動く | 食べたい料理を入力して「おすすめを表示」を押すと回答が表示される |

## よくあるトラブルと対処法

### ページが表示されない（AccessDenied エラー）

- CloudFront ディストリビューションの **「デフォルトルートオブジェクト」** に `index.html` が設定されているか確認
  - 設定場所：CloudFront → ディストリビューション → 「全般」タブ → 「設定を編集」
  - 空欄のままだと `/` アクセス時に AccessDenied になります

### ページが表示されない（403 Forbidden エラー）

- バケットポリシーが正しく設定されているか確認
- 「パブリックアクセスをすべてブロック」がオフになっているか確認
- バケットポリシーの `Resource` のバケット名が正しいか確認

### 写真が表示されない

- `photo1.png`・`photo2.png` が S3 にアップロードされているか確認
- ファイル名が正確に一致しているか確認（大文字・小文字の違いに注意）

### AI おすすめ機能が動かない

- `index.html` は書き換えず、Session4 で `Session1/config.js` の `window.BEDROCK_API_ENDPOINT`（Amplify なら同名の環境変数）に HTTP API の URL を設定します。このセッションの時点では、AI おすすめは「Session4 で設定します」と表示されるのが正常です
